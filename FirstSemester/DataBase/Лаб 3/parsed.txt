Завдання 1. Створення БД для предметної області «Спортивний клуб»
Базу даних створено для предметної області, обраної в лабораторній роботі № 1, — «Робота спортивного клубу». БД має назву sport_club і кодування utf8mb4, щоб коректно зберігати український текст. На початку сценарію стоїть DROP DATABASE IF EXISTS: так сценарій можна запускати повторно й щоразу отримувати «чисту» БД. Команда USE робить БД активною для подальших операторів.

Завдання 2. Створення таблиць БД та визначення ключових полів
Таблиці створено відповідно до фізичної моделі, побудованої в DbDesigner у лабораторній роботі № 2. Первинний ключ кожної таблиці — цілочисельне поле з атрибутом AUTO_INCREMENT. Зв’язки між таблицями задано обмеженнями FOREIGN KEY ... REFERENCES. Таблиці створюються в такому порядку, щоб таблиця, на яку посилається зовнішній ключ, на момент створення вже існувала.
Окремим блоком через ALTER TABLE додано обмеження цілісності: CHECK для площі, місткості, часу та вартості й UNIQUE для номера телефону відвідувача. Склад стовпців і зв’язки при цьому не змінюються, тож модель залишається ідентичною моделі з ЛР2.

Таблиці наповнено багаторядковими операторами INSERT INTO ... VALUES. Спочатку заповнюються довідкові таблиці (hall, visitor, employee, equipment_category), потім таблиці, які посилаються на них. Інакше спрацює обмеження зовнішнього ключа. У кожній таблиці не менше 10 записів.

Завдання 4. Генерація EER-моделі БД та порівняння з моделлю DbDesigner
EER-модель згенеровано засобами MySQL Workbench зі створеної БД (зворотне проєктування):
1) меню Database → Reverse Engineer… (Ctrl+R);
2) обрати з’єднання Local instance та ввести пароль користувача root, Next;
3) у списку схем позначити sport_club, Next → Execute;
4) залишити позначку «Place imported objects on a diagram», Execute → Next → Finish.
Workbench відкриває EER-діаграму, побудовану за структурою створених таблиць.

Висновки
У лабораторній роботі засобами SQL у MySQL Workbench створено базу даних sport_club для предметної області «Спортивний клуб». Сценарій створення БД можна запускати повторно: DROP DATABASE IF EXISTS та CREATE DATABASE IF NOT EXISTS щоразу дають однаковий результат.
Створено 9 таблиць із первинними ключами AUTO_INCREMENT і 9 зовнішніми ключами. За допомогою ALTER TABLE додано обмеження CHECK та UNIQUE, тож СКБД сама не дає внести некоректні дані (від’ємну площу, час виходу раніше за час входу, повторний номер телефону).
Таблиці наповнено тестовими даними: від 10 до 36 записів у кожній. EER-модель, згенерована Workbench, повністю збігається з фізичною моделлю, побудованою в DbDesigner у ЛР2. Отже, SQL-сценарії реалізують спроєктовану структуру БД без відхилень.
