Тема 1

Сучасний Веб: основні поняття та еволюція

🌐 Інтернет vs Служба Веб (WWW)

Інтернет — глобальна фізична та логічна інфраструктура комп'ютерних мереж і ліній зв'язку.

Служба Веб (World Wide Web) — інформаційна система взаємопов'язаних вебдокументів (вебресурсів), доступних через мережу Інтернет за протоколом HTTP/HTTPS.

  • Маршрутизатори (Routers): спеціалізовані мережні пристрої, які за алгоритмами маршрутизації направляють пакети даних оптимальним шляхом між клієнтом і сервером.
  • Клієнт: пристрій користувача (ПК, ноутбук, смартфон, IoT), що формує і відправляє запит.
  • Сервер: обчислювальна машина, що цілодобово обробляє запити і повертає ресурси (вебсервер, поштовий, ігровий, медіа).
📡 Стримінг та Категорії послуг

Технологія стримінгу (Streaming): безперервна передача аудіо чи відеопотоку в режимі реального часу від сервера до клієнта без потреби повного попереднього завантаження файлу на диск.

  • Комунікаційні послуги: месенджери, соцмережі, чати, спільна взаємодія користувачів у реальному часі.
  • Інформаційні послуги: пошукові машини, бази знань, онлайн-медіа.
  • Хмарні послуги: віддалене збереження файлів та обчислення (Google Drive, AWS, Azure).
  • Розважальні послуги: онлайн-ігри, стримінгові кінотеатри, музичні платформи.
🚀 Еволюція Веб (Web 1.0 → 2.0 → 3.0)
  • Web 1.0 («Read-Only»): статичні HTML-сторінки, контент створюють лише вебмайстри, відсутність взаємодії з користувачем.
  • Web 2.0 («Read-Write»): динамічний контент, платформи для користувацького контенту (UGC), соцмережі, блоги, інтернет-банкінг, AJAX.
  • Web 3.0 («Read-Write-Execute / Semantic»): децентралізовані мережі, семантичний веб, машинне розуміння даних, штучний інтелект та смартконтракти.
⚡ Питання з білетів КР:

• Через які пристрої прокладається шлях для інформаційних потоків у мережі? → Маршрутизатори.

• Яка категорія послуг забезпечує взаємодію користувачів у реальному часі? → Комунікаційні послуги.

• Що характеризує технологію стримінгу? → Безперервна передача медіаданих без повного попереднього завантаження.

Тема 2

Основні типи вебресурсів

📂 Чотири типи вебресурсів
  • Вебсайт: сукупність пов'язаних сторінок під одним доменом для презентації інформації (візитки, блоги, медіа).
  • Вебдодаток (Web App): інтерактивна програма в браузері зі складною логікою та роботою зі станом (Gmail, Trello, онлайн-редактори).
  • Вебсервіс: програмна одиниця (API/ендпоінт), призначена для машинної взаємодії між додатками через мережу без обов'язкового UI.
  • Вебплатформа: екосистема, що поєднує додатки, сервіси та інфраструктуру (Shopify, WordPress, соціальні платформи).
⚡ Статичний vs Динамічний контент

Статичний контент: файли (HTML, CSS, JS, картинки), готові на сервері завчасно. Для всіх користувачів повертаються однаковими. Легко кешуються CDN та браузером.

Динамічний контент: сторінки, які формуються бекендом або JavaScript у момент запиту на основі бази даних, параметрів авторизації та вподобань користувача.

Чому важко кешувати динамічний контент? Він залежить від індивідуального користувача та часто змінюється, тому кеш миттєво втрачає актуальність.
🏗️ Архітектурні моделі (MPA, SPA, PWA)
  • MPA (Multi-Page App): традиційний підхід, де кожен клік на посилання спричиняє повне перезавантаження всієї HTML-сторінки із сервера.
  • SPA (Single-Page App): один кореневий HTML-файл; контент перемальовується JavaScript на льоту без повного перезавантаження вікна.
  • PWA (Progressive Web App): вебдодаток з можливістю встановлення на робочий стіл смартфона/ПК, підтримкою офлайн-роботи через Service Workers та Push-повідомленнями.
Тема 3

Технологічна екосистема інтернету

🔄 Життєвий цикл HTTP-запиту
  1. Користувач вводить домен (наприклад, site.ua) у браузер.
  2. DNS-сервер перетворює символьний домен на IP-адресу сервера.
  3. Браузер відправляє HTTP/HTTPS запит через маршрутизатори на вебсервер.
  4. Вебсервер (Nginx/Apache) передає запит серверному додатку.
  5. Додаток звертається до Бази Даних і формує відповідь (HTML/JSON).
  6. Браузер отримує відповідь і запускає процес візуалізації (рендеринг).
🔒 Хостинг, DNS та SSL/TLS
  • Хостинг: послуга надання фізичного або віртуального дискового простору та обчислювальних потужностей сервера для розміщення вебресурсів.
  • DNS (Domain Name System): розподілена база даних, що транслює людинозрозумілі імена в числові IP-адреси.
  • SSL/TLS-сертифікат: цифровий сертифікат, виданий центром сертифікації (CA), що підтверджує справжність сайту та забезпечує шифрування каналу зв'язку за протоколом HTTPS.
🔌 Що таке API?

API (Application Programming Interface): стандартний програмний інтерфейс, за допомогою якого різні програмні продукти обмінюються даними та командами без знання внутрішньої реалізації один одного.

Типовий формат обміну даними сучасних веб-API: JSON (JavaScript Object Notation).

Тема 4

Базові технології фронтенду та бекенду

Параметр Фронтенд (Frontend / Client-side) Бекенд (Backend / Server-side)
Де виконується код? У браузері клієнта на комп'ютері або смартфоні На вебсервері в дата-центрі або хмарі
Базовий стек мов HTML (структура), CSS (оформлення), JavaScript (логіка) PHP, Python, Java, C#, Go, Node.js, Ruby (HTML тут НЕ використовується!)
Головні задачі Інтерфейс, відображення даних, інтерактивність, анімація, UX Бізнес-логіка, робота з СУБД, авторизація, платежі, захист даних
⚖️ Бібліотека vs Фреймворк

Бібліотека: набір допоміжних готових функцій і класів для вирішення вузьких завдань. Ваш код керує бібліотекою і викликає її тоді, коли це потрібно.

Фреймворк: каркас і архітектурний шаблон усього додатку. Працює принцип Inversion of Control (IoC): фреймворк керує життєвим циклом програми та сам викликає написані вами модулі.

🐙 Контроль версій (Git & GitHub)
  • Git: розподілена система контролю версій для локального відстеження змін у коді, створення гілок і комітів.
  • GitHub / GitLab: хмарний вебсервіс для розміщення віддалених репозиторіїв Git, командної роботи та CI/CD.
Тема 5

HTML: структура та семантика вебдокумента

🧱 Базовий скелет сторінки
<!DOCTYPE html>
<html lang="uk">
  <head>
    <meta charset="UTF-8">
    <title>Заголовок вкладки</title>
  </head>
  <body>
    <h1>Видимий контент</h1>
  </body>
</html>
  • <html>: кореневий елемент усього документа.
  • <head>: технічні метадані, кодування, підключення стилів і скриптів. Безпосередньо у вікні не відображаються.
  • <body>: видимий для користувача вміст.
🏷️ Одинарні vs Парні теги
  • Парні теги: мають відкриваючий та закриваючий теги, містять всередині контент або інші теги: <p>текст</p>, <h1>...</h1>, <strong>...</strong>, <div>...</div>.
  • Одинарні (самозакривні): не містять вкладеного тексту, вся інформація передається атрибутами: <img>, <input>, <br>, <hr>, <meta>.
  • Обов'язкові атрибути: для <img> обов'язковим є src (шлях до картинки), атрибут alt служить для опису зображення; для <a> обов'язковим є href.
📦 Блокові vs Рядкові (Inline) елементи

Блокові (`display: block`): <div>, <p>, <h1>..<h6>, <ul>, <section>. Завжди починаються з нового рядка і розтягуються на всю доступну ширину контейнера.

Рядкові (`display: inline`): <a>, <span>, <strong>, <em>. Розташовуються в один рядок один за одним. Не реагують на встановлення властивостей width та height.

Тема 6

CSS: стилізація, адаптивність, Flexbox і Grid

🎯 Селектори та специфічність
  • Тег: p { color: red; } (вага: 0,0,1).
  • Клас: .btn { padding: 10px; } (вага: 0,1,0).
  • Ідентифікатор: #header { background: blue; } (вага: 1,0,0).
  • Прямий дочірній елемент: p > strong (вибирає strong тільки першого рівня вкладеності в p).
  • Будь-який нащадок: p strong (вибирає на будь-якій глибині).
  • !important: ламає нормальний каскад і надає правилу найвищий пріоритет.
👁️ display vs visibility
  • display: inline-block; — елемент стоїть у рядку поряд з іншими, але підтримує властивості width, height, margin та padding.
  • display: none; — елемент повністю вилучається з потоку документа (місце не займається).
  • visibility: hidden; — елемент стає невидимим, але його фізичне місце в макеті залишається зайнятим.
  • Псевдоелементи ::before та ::after вимагають обов'язкової властивості content: "".
📏 Одиниці виміру
  • px: абсолютна одиниця виміру (пікселі екрана).
  • rem: відносно розміру шрифту кореневого елемента <html> (за замовчуванням 16px).
  • em: відносно шрифту найближчого батьківського елемента.
  • vw / vh: 1% від ширини / висоти вікна перегляду (viewport).
  • fr: fraction (частка вільного місця в CSS Grid).
Критерій Flexbox (Flexible Box) CSS Grid
Вимірність Одновимірна система (або рядок, або колонка) Двовимірна система (рядки і колонки одночасно)
Основні властивості justify-content (головна вісь), align-items (поперечна), flex-wrap: wrap grid-template-columns, grid-template-rows, одиниця fr, gap
Оптимальне застосування Меню, панелі кнопок, ряди карток, центрування блоку Загальна сітка сайту, складні табличні галереї, дашборди
Тема 7

JavaScript: інтерактивність і логіка вебсторінки

⚡ Критичний шлях рендерингу (CRP)

Як браузер перетворює код на пікселі:

  1. Парсинг HTML → створення дерева DOM.
  2. Парсинг CSS → створення дерева CSSOM.
  3. Об'єднання DOM + CSSOM → створення Render Tree (дерева рендерингу).
  4. Layout (Компонування / Reflow): розрахунок геометрії та координат елементів.
  5. Paint (Відмальовка): заповнення пікселів на екрані.
Що не потрапляє в Render Tree? Теги <head>, <script>, <meta> та будь-які елементи зі стилем display: none.
🔄 Тріада інтерактивності JS

Подія (Event) → Зміна стану (State) → Оновлення DOM

Користувач натискає кнопку (подія `click`), скрипт змінює внутрішні дані програми (стан) і вносить зміни в потрібний вузол DOM (наприклад, element.textContent = 'Збережено').

☕ Ванільний JS vs Фреймворки

Ванільний (чистий) JavaScript:

  • Коли брати: прості скрипти, ізольовані інтерактивні елементи (модальне вікно, меню-бургер, слайдер), де непотрібно тягнути зайві мегабайти бібліотек.
  • Обмеження у великих проектах: важко контролювати синхронізацію стану, ризик заплутаного спагеті-коду, рутинне низькорівневе оновлення DOM.

Фреймворки (React, Vue, Angular): вирішують проблеми стану за допомогою компонентної архітектури та Virtual DOM.

Тема 8

Комп’ютерна графіка

🖼️ Растрова vs Векторна графіка

Растрова: сітка кольорових пікселів. При збільшенні масштабу пікселізується та втрачає чіткість. Ідеальна для фотографій та реалістичних картин (JPEG, PNG, WebP).

Векторна: математичні координати, вектори, лінії та формули Безьє. Масштабується нескінченно без втрати чіткості на будь-яких екранах. Ідеальна для логотипів, іконок, графіків (SVG).

🎨 Колірні моделі (RGB, CMYK, HSB)
  • RGB (Red, Green, Blue): адитивна модель (випромінювання світла). Застосовується в моніторах, телевізорах, смартфонах. При максимальному змішуванні (255,255,255) дає білий колір (White).
  • CMYK (Cyan, Magenta, Yellow, Key/Black): субтрактивна модель (поглинання світла фарбою). Застосовується в поліграфії та друці.
  • HSB (Hue, Saturation, Brightness): психологічна модель: колірний тон, насиченість та яскравість.
📊 Формати веб-зображень
  • JPEG: стиснення з втратами, ідеальний для фотографій, не підтримує прозорість.
  • PNG: стиснення без втрат, підтримує альфа-прозорість, важчий за JPEG.
  • WebP: сучасний високоефективний формат Google. Підтримує стиснення як з втратами, так і без втрат, прозорість та анімацію.
  • SVG: векторний формат на основі мови XML, безпосередньо стилізується через CSS.
Тема 9

Комп’ютерні шрифти

✍️ Класифікація гарнітур
  • Serif (із засічками): мають невеликі штрихи-засічки на кінцях літер (Times New Roman, Georgia). Традиційні для друку та художніх видань.
  • Sans-serif (рублені / без засічок): прямі рівні лінії без засічок (Arial, Inter, Roboto). Найкраще читаються з екранів моніторів.
  • Monospace (моноширинні): усі літери мають однакову ширину (Courier, JetBrains Mono). Використовуються для коду і таблиць.
💻 Веб-безпечні vs Веб-шрифти

Веб-безпечні (Web-safe): шрифти, гарантовано присутні на більшості ОС користувачів (Arial, Verdana, Times New Roman, Tahoma). Не потребують завантаження з мережі.

Веб-шрифти (Web Fonts): кастомні шрифти, які браузер завантажує за правилом @font-face. Сучасні стиснені формати: WOFF2 (найефективніший) та WOFF.

Тема 10

Інформаційне наповнення вебресурсу

👁️ Сприйняття вебконтенту

Користувачі в інтернеті сканують сторінки поглядом (F-патерн), шукаючи очима заголовки, списки та жирний шрифт, а не читають суцільний текст від початку до кінця.

Текст має бути структурований: інформативні підзаголовки `h2/h3`, короткі абзаци (3-4 рядки), марковані списки.

🎯 Намір користувача (User Intent)
  • Інформаційний: отримати конкретну відповідь або знання («що таке flexbox»).
  • Навігаційний: перейти на відомий ресурс («вхід пошта львівська політехніка»).
  • Транзакційний: здійснити швидку дію: купити, зареєструватися, оплатити квиток.
  • Комерційний: порівняти характеристики або відгуки перед покупкою.
📝 Копірайтинг vs Рерайтинг
  • Копірайтинг: створення повністю унікального авторського тексту на основі знань, аналізу та особистого досвіду.
  • Рерайтинг: переписування готових текстових матеріалів своїми словами зі збереженням вихідних фактів.
  • Унікальність: важлива для захисту від фільтрів пошукових систем та зростання авторитетності ресурсу.

🎨 Інтерактивний тренажер: Завдання №13 (Системи кольору)

Вартість: 3 бали

Оберіть колір з білета та встановіть повзунок непрозорості. Калькулятор автоматично згенерує всі 4 поля для запису у бланк і підсвітить колірні круги.

Зразок відтінку
