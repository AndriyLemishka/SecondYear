## 1. Загальна інженерна стратегія взаємодії з ШІ-інструментами

У ході виконання лабораторної роботи №6 реалізовано повноцінний ітеративний інженерний цикл **Prompt-to-UI & Refinement Workflow**:
$$\text{Інженерний промпт} \longrightarrow \text{ШІ-генерація компонента} \longrightarrow \text{Аналіз коду студентом} \longrightarrow \text{Тестування в Tailwind Play / DevTools} \longrightarrow \text{Рафінування}$$

Для виконання вимог методичних вказівок було залучено комплекс провідних ШІ-систем та протоколів:
1. **Claude (Anthropic, модель Claude 3.5 Sonnet)** — основний інструмент генерації ізольованих компонентів на базі HTML5 + Tailwind CSS, проєктування семантичної навігації та компонування складних сіток.
2. **Google Gemini (Gemini Advanced with Thinking)** — порівняльний аналіз архітектурних рішень, оцінка відповідності брейкпоїнтів та тестування інженерних запитів в освітньому профілі корпоративного облікового запису LPNU.
3. **Sequential Thinking MCP Server** — покроковий логічний аналіз структури брейкпоїнтів, обчислення контрастності кольорів та перевірки граничних станів (Edge Cases).
4. **Chrome DevTools MCP** — автоматизоване тестування адаптивності у режимі Device Toolbar (Mobile 375px, Tablet 768px, Desktop 1440px) та зняття верифікаційних знімків екрана.

## 2. Журнал ітерацій (Prompt Log)

### Промпт 1. Створення першого ізольованого UI-компонента: Primary CTA Button (Етап 5)

- **Ціль:** Згенерувати доступну, зручну для сенсорного введення кнопку головної дії з інтерактивними станами без використання власного CSS чи сторонніх бібліотек.
- **Модель:** Claude 3.5 Sonnet / Gemini.
- **Рольова установка (System/Persona):** `Senior Frontend Developer & UI Engineer`.

#### Текст промпту:
```text
Ти — Senior Frontend Developer та UI Engineer.
Створи ізольований компонент Primary CTA Button «Дізнатися більше» за допомогою HTML5 та Tailwind CSS.

Технічні вимоги:
1. Колір фону: #2563EB (Tailwind bg-blue-600) з переходом у темніший відтінок при наведенні.
2. Текст: білий, 16px, напівжирний (font-semibold).
3. Внутрішні відступи: padding 12px 24px (py-3 px-6).
4. Скруглення кутів: border-radius 12px (rounded-xl).
5. Інтерактивні стани:
   - hover: плавне затемнення фону та збільшення тіні;
   - active: легке тактильне стискання (scale-95);
   - disabled: стан блокування з курсором not-allowed та зниженою прозорістю;
   - focus-visible: чітке двоколірне фокусне кільце (ring) для навігації з клавіатури без появи обведення при кліку мишкою.
6. Плавні переходи: transition-all duration-200.
7. Доступність (Accessibility): мінімальна висота 44px згідно з критеріями WCAG 2.5.5 / 2.5.8 (Touch Target Minimum).
8. Не використовуй Bootstrap, JavaScript або власні стилі CSS. Після коду дай стисле пояснення кожного використаного Tailwind-класу.
```

#### Результати генерації та аналіз:
- ШІ коректно реалізував базову кнопку та використав класи `inline-flex items-center justify-center min-h-[44px] px-6 py-3 bg-blue-600 hover:bg-blue-700 active:scale-95 text-white font-semibold text-base rounded-xl shadow-md transition-all duration-200`.
- **Аналіз студента:** ШІ спочатку не врахував стан `focus-visible`, додавши звичайний `focus:ring-2`. Студент додав `focus-visible:outline-none focus-visible:ring-4 focus-visible:ring-blue-300`, що гарантує відсутність настирливого контуру при кліку мишкою для звичайних користувачів, але зберігає обов'язковий фокус для клавіатури.

- **Ціль:** Створити адаптивну шапку сайту відповідно до макета Figma (ЛР №4), де на десктопі показується повний список посилань, випадний список та кнопки входу, а на мобільних пристроях — кнопка гамбургер-меню з повноцінним висувним меню.

#### Текст промпту:
```text
Ти — Senior Frontend Developer та UI Engineer.
Створи ізольований семантичний компонент Header для мого вебпроєкту національної мережі швидкісних зарядних станцій електромобілів «ChargeUA».
Використовуй HTML5 та Tailwind CSS.

Структура компонента:

4. Мобільна адаптивність (Mobile First):
```

- Забезпечено повне перемикання станів за допомогою чистого JS-скрипта (3 рядки коду з підтримкою закриття клавішею `Escape`).

### Промпт 6. Аналіз ШІ-коду та покрокове рафінування (Етап 12 та 17)

- **Ціль:** Проаналізувати згенерований ШІ код, виявити сильні сторони, сумнівні рішення та внесені без узгодження зміни; провести рефакторинг.
- **Модель:** Claude 3.5 Sonnet / Gemini Thinking.

#### Текст промпту:
```text
Проаналізуй створений тобою комплексний Tailwind-код компонентів Header, Card, Grid та Footer. Не переписуй код.
Знайди та чітко сформулюй:
1. Одне правильне і технічно бездоганне рішення.
2. Одне сумнівне або неоптимальне рішення (наприклад, arbitrary values, специфічність або доступність).
3. Одну зміну, яку ти додав самостійно без прямої вказівки у промпті.
Запропонуй точні правила рефакторингу для усунення виявлених недоліків.
```

#### Висновки рафінування (Refinement Log):
1. **Правильне рішення:** Використання utility `min-h-[44px]` та `focus-visible:ring-4` для всіх кнопок дій, що забезпечило відповідність найсуворішим критеріям WCAG 2.2 AA.
2. **Сумнівне рішення:** ШІ спочатку захардкодив кольори через довільні квадратні дужки на зразок `bg-[#005EC9]` замість підключення семантичної теми `tailwind.config` (`bg-blue-600` / `bg-brand-500`). Це ускладнює подальшу глобальну підтримку теми (Theming).
3. **Самостійна зміна ШІ:** Модель самостійно згенерувала SVG-іконки стрілочок всередині кнопок, хоча у промпті запитувався лише текст.
4. **Виправлення:** Всі довільні значення винесені в об'єкт конфігурації `tailwind.config`, додано повноцінне ARIA-керування для мобільного меню (`aria-expanded`, блокування клавішею Escape), а зображення отримали вичерпні українськомовні описи в атрибутах `alt`.
