# Лабораторна робота №5
## Тема: Робота з об'єктами Active Directory на платформі Windows Server

**Мета роботи:** Ознайомитися з установкою контролера домену, DNS- та DHCP-серверів на платформі операційної системи Windows Server. Ознайомитися з налаштуванням профілів користувачів домену Windows Server. Вивчити способи завдання групових політик, види параметрів групових політик, об’єкти групових політик, навчитися задавати групові політики для різних об’єктів.

**Обладнання та програмне забезпечення:** 
* Середовище віртуалізації Oracle VM VirtualBox;
* Серверна операційна система Microsoft Windows Server (контролер домену `Server`);
* Клієнтська операційна система Microsoft Windows (робоча станція клієнта);
* Служби та оснастки адміністрування: Active Directory Domain Services (AD DS), DNS Server, DHCP Server, Active Directory Users and Computers (`dsa.msc`), Group Policy Management Console (`gpmc.msc`), Microsoft Management Console (`mmc.exe`).

---

## 1. Теоретичні відомості

### 1.1. Служба каталогів Active Directory (AD DS)
**Active Directory (AD)** — це масштабована LDAP-сумісна розподілена служба каталогів, розроблена корпорацією Microsoft для сімейства операційних систем Windows NT / Server. Active Directory забезпечує централізоване керування автентифікацією, авторизацією та конфігурацією всіх ресурсів мережі (комп'ютерів, облікових записів користувачів, груп безпеки, мережевих принтерів, спільних папок та політик безпеки).

Основні компоненти логічної структури AD:
* **Об'єкти (Objects):** базові елементи каталогу (користувач, комп'ютер, група, спільний ресурс).
* **Організаційні підрозділи (Organizational Units, OU):** контейнери всередині домену, які використовуються для логічного групування об'єктів за географічною або функціональною ознакою та слугують базовим рівнем прив'язки групових політик (GPO).
* **Домен (Domain):** фундаментальна межа адміністрування та безпеки. Усі об'єкти всередині домену підпорядковуються спільним політикам безпеки та єдиній базі даних `NTDS.dit`.
* **Дерево та Ліс (Tree & Forest):** об'єднання одного або декількох доменів, які мають спільну схему каталогу, глобальний каталог (Global Catalog) та транзитивні двосторонні довірчі зв'язки за протоколом Kerberos.

### 1.2. Групові політики (Group Policy Object, GPO)
**Групова політика (GPO)** — механізм централізованого керування конфігурацією ОС Windows, системних служб та прикладного програмного забезпечення. 
Об'єкт GPO складається з двох частин:
1. **GPC (Group Policy Container):** об'єкт в базі Active Directory, що зберігає атрибути версії та статус політики.
2. **GPT (Group Policy Template):** каталог файлової структури у спільній папці `SYSVOL` контролера домену, що містить фактичні налаштування (`Registry.pol`, скрипти, шаблони безпеки).

Порядок застосування політик підпорядковується правилу **LSDOU**:
1. **L**ocal (Локальна політика комп'ютера);
2. **S**ite (Політика сайту Active Directory);
3. **D**omain (Політика домену, наприклад Default Domain Policy);
4. **OU** (Політики організаційних підрозділів — застосовуються зверху вниз за ієрархією).

### 1.3. Типи облікових записів та профілів користувачів
В ОС Windows розрізняють:
* **Локальний обліковий запис:** діє лише на одному ізольованому комп'ютері, зберігається у локальній базі SAM (`%SystemRoot%\System32\config\SAM`).
* **Доменний обліковий запис:** діє в межах усього домену, зберігається централізовано в Active Directory.
* **Локальний профіль користувача:** зберігається на локальному диску (`C:\Users\<Username>`).
* **Переміщуваний профіль (Roaming User Profile):** конфігурація та робочий стіл користувача копіюються на мережевий сервер (`\\server\Profiles\%Username%`) і завантажуються на будь-який доменний комп'ютер під час входу.
* **Обов'язковий профіль (Mandatory Profile):** різновид переміщуваного профілю, у якому файл налаштувань реєстру `Ntuser.dat` перейменовується на `Ntuser.man`. Усі зміни, зроблені користувачем під час сеансу (створені ярлики, налаштування програм), безповоротно стираються після виходу з системи.

## 2. Хід виконання роботи

### Завдання 1. Розгортання контролера домену, DNS- та DHCP-серверів

1. **Базове налаштування сервера:**
   * Запущено віртуальну машину Windows Server у середовищі VirtualBox.
   * Здійснено вхід під вбудованим обліковим записом `Administrator` з паролем `Pa$$word`.
   * Комп'ютеру призначено мережеве ім'я `Server`.
   * Для мережевого інтерфейсу встановлено статичні параметри TCP/IPv4:
     * **IP-адреса:** `192.168.1.5`
     * **Маска підмережі:** `255.255.255.0`
     * **Основний шлюз:** `192.168.1.4`
     * **Віддаваний DNS-сервер:** `192.168.1.5` (вказує на себе).

2. **Встановлення ролей сервера та підвищення до контролера домену (DC):**
   * Встановлено роль «Доменні служби Active Directory» (Active Directory Domain Services).
   * Запущено майстер розгортання домену `dcpromo.exe`.
   * Обрано конфігурацію: **«Створити новий домен у новому лісі»**.
   * Повне доменне ім'я кореневого домену лісу (FQDN): `office.com`.
   * Рівень функціонального режиму лісу та домену: **Windows Server 2008**.
   * Додатково активовано та сконфігуровано роль **DNS-сервера** (інтегрована в Active Directory зона `office.com`).

3. **Встановлення та параметризація DHCP-сервера:**
   * Додано роль «DHCP-сервер».
   * Створено та активовано нову область (DHCP Scope) згідно з параметрами Таблиці 1:

**Таблиця 1. Параметри налаштування DHCP-сервера**

| № | Параметр налаштування | Значення |
|---|---|---|
| 1 | Назва області DHCP | Офіс |
| 2 | Початкова та кінцева IP-адреси | 192.168.1.1 — 192.168.1.200 |
| 3 | Діапазон адрес виключення | 192.168.1.150 — 192.168.1.170 |
| 4 | Окремі виключені адреси | 192.168.1.2, 192.168.1.3 |
| 5 | Тривалість оренди (Lease Duration) | 8 днів |
| 6 | Маршрутизатор за замовчуванням (Шлюз) | 192.168.1.4 |
| 7 | Зарезервована IP-адреса | Ім'я клієнта: `шлюз`<br>IP: `192.168.1.4`<br>MAC-адреса: `1a-2b-3c-4d-5e-6f` |

### Завдання 3. Налаштування об'єкта групової політики (GPO) для підрозділу

1. Запущено оснастку **«Керування груповою політикою»** (`gpmc.msc`).
2. Для підрозділу `Фінансисти` створено новий об'єкт групової політики під назвою **«Фінансова політика безпеки»** та зв'язано його з цим OU.
3. У Редакторі керування груповими політиками перейдено до гілки:  
   `Конфігурація користувача -> Політики -> Адміністративні шаблони -> Панель керування -> Персоналізація`.
4. Сконфігуровано параметри безпеки:
   * **Тайм-аут заставки (Screen saver timeout):** Стан — *Увімкнено*, Час очікування — *600 секунд* (10 хвилин). Внесено коментар «Фінансова політика безпеки».
   * **Парольний захист заставки (Password protect the screen saver):** Стан — *Увімкнено*. Внесено коментар «Фінансова політика безпеки».
5. Застосовано примусове оновлення політик у системі командою `gpupdate /force`.

### Завдання 4. Конфігурація мережевих спільних ресурсів та домашніх дисків

1. На системному диску `C:` сервера створено каталог `C:\Офіс`.
2. У вікні властивостей каталогу налаштовано комбіновані права доступу:
   * **Мережевий доступ (SMB Share Permissions):**  
     На вкладці *«Доступ -> Розширене налаштування -> Дозволи»* групі `Domain Users` надано дозволи: **Зміна (Change)** та **Читання (Read)**.
   * **Рівень безпеки файлової системи (NTFS Permissions):**  
     На вкладці *«Безпека»* користувачам домену надано права: **Читання, перегляд вмісту папки та виконання**.
3. Усередині каталогу `C:\Офіс` створено ізольовані підпапки для підрозділів: `Керівники`, `Фінансисти`, `IT-спеціалісти`.
4. Для кожної підпапки за допомогою списків контролю доступу (ACL) встановлено права на зміну даних виключно для відповідної групи безпеки (`Modify` для групи підрозділу).
5. В оснастці `dsa.msc` у властивостях облікового запису `Програміст` на вкладці *«Профіль»* налаштовано автоматичне монтування домашньої мережевої папки під літерою **P:** за мережевим UNC-шляхом: `\\server\Офіс`.

### Завдання 5. Налаштування переміщуваних (Roaming) та обов'язкових (Mandatory) профілів

1. **Створення централізованого сховища профілів:**
   * На сервері створено каталог `C:\Profiles` та надано до нього повний спільний доступ (`Full Control`) для облікових записів системи та користувачів домену.
2. **Переміщуваний профіль користувача `Сервіс-інженер`:**
   * У властивостях користувача вказано шлях до профілю: `\\server\Profiles\%Username%`.
   * При вході користувача `Сервіс-інженер` з робочої станції автоматично генерується профіль.
   * На робочому столі користувача створено папку `Клієнти`. При завершенні сеансу вміст синхронізовано на сервер.
3. **Обов'язковий профіль користувача `Менеджер`:**
   * Для облікового запису `Менеджер` вказано мережевий шлях: `\\server\Profiles\%Username%`.
   * Після першого сеансу файл конфігурації куща реєстру користувача `Ntuser.dat` на сервері перейменовано на `Ntuser.man`.
   * **Перевірка захисту обов'язкового профілю:**  
     Користувач `Менеджер` створив на робочому столі каталог «Шеф - завжди правий». Після завершення роботи та повторного входу каталог безповоротно зник, що підтверджує незмінність та захист обов'язкового профілю від модифікації.

### Завдання 6. Налаштування доменної політики складності паролів

Через оснастку `mmc.exe` у розділі `Default Domain Policy` (`Конфігурація комп'ютера -> Налаштування Windows -> Параметри безпеки -> Політики облікових записів -> Політика паролів`) встановлено загальнодоменні правила:
* **Мінімальна довжина пароля:** не менше 8 символів;
* **Збереження журналу паролів (історія):** 3 попередні паролі;
* **Вимоги складності паролів:** Увімкнено (обов'язкова наявність великих/малих літер, цифр та спеціальних символів);
* **Максимальний термін дії пароля:** 60 днів.

### Завдання 7. Політика блокування облікових записів (Account Lockout Policy)

У розділі `Політика блокування облікового запису` (Account Lockout Policy) сконфігуровано:
* **Поріг блокування облікового запису:** 3 невдалі спроби входу;
* **Тривалість блокування облікового запису:** 5 хвилин;
* **Скидання лічильника блокування через:** 5 хвилин.

### Завдання 9. Приєднання клієнтської робочої станції до домену

2. Запущено майстер мережевої ідентифікації (`Network Identification Wizard`) у вікні `Властивості системи -> Ім'я комп'ютера`.
3. Виконано введення комп'ютера в домен `office.com` (або `faculty.ua`) за допомогою авторизаційних даних облікового запису `Administrator`.
4. Комп'ютер успішно перезавантажено та зареєстровано в контейнері `Computers` контролера домену.

### Завдання 10–11. Спільні папки та запуск програм через механізм «Run As»

2. **Дослідження механізму «Run As» (Запустити від імені):**

   * Використовуючи комбінацію `Shift + Правий клік -> Run as different user`, введено реквізити `office.com\Administrator` та пароль `Pa$$word`, що дозволило безпечно виконати адміністративну програму без перемикання глобального сеансу Windows.

### Завдання 12. Скрипти міграції SQL Server Reporting Services (rs.exe)

Досліджено сценарії реплікації та перенесення звітів між серверами SQL Server Reporting Services (SSRS) за допомогою консольної утиліти `rs.exe` та скрипту `ssrs_migration.rss`:

**Таблиця 3. Підтримувані сценарії міграції серверів звітів**

| Ім'я сервера | Режим сервера звітів (Report Server Mode) |
|---|---|
| Сервер А | Власний (Native Mode) |
| Сервер В | SharePoint Integrated Mode |
| Сервер С | SharePoint Integrated Mode |

Команда запуску міграції між серверами:
```cmd
rs.exe -i ssrs_migration.rss -e Mgmt2010 -s https://SourceServer/ReportServer -u Domain\User -p password -v ts="https://TargetServer/reportserver" -v tu="Domain\Userser" -v tp="password" -v security="True"
```
Міграція виконується у 2 етапи:
1. **Етап 1 (Аудит):** формування переліку ролей (`Browser`, `Content Manager`, `System Administrator`), розкладів та джерел даних без виконання запису.
2. **Етап 2 (Міграція):** перенесення звітів та безпекових дескрипторів без перезапису існуючих елементів з аналогічними іменами.

## 3. Відповіді на контрольні запитання

1. **Що таке Active Directory та яка її основна функція?**  
   *Відповідь:* Active Directory — це ієрархічна служба каталогів для ОС Windows Server. Вона забезпечує централізовану автентифікацію, авторизацію, збереження інформації про облікові записи користувачів, комп'ютери та мережеві ресурси, а також управління ними через механізм групових політик.

2. **Чим відрізняється робоча група (Workgroup) від домену (Domain)?**  
   *Відповідь:* У робочій групі кожен комп'ютер є автономним і зберігає власну локальну базу облікових записів (SAM). У домені база даних є єдиною і централізованою (`NTDS.dit`), адміністрування облікових записів та правил безпеки здійснюється з контролера домену (DC).

3. **Яка різниця між переміщуваним (Roaming) та обов'язковим (Mandatory) профілем?**  
   *Відповідь:* У переміщуваному профілі всі налаштування та файли користувача зберігаються на сервері при виході з системи і відновлюються під час наступного входу на будь-якому ПК домену. В обов'язковому профілі (`Ntuser.man`) користувач може змінювати робоче середовище лише під час поточного сеансу — після виходу всі зміни скидаються до еталонного стану.

4. **Для чого використовується утиліта dcpromo?**  
   *Відповідь:* Утиліта `dcpromo` (Domain Controller Promoter) використовується для підвищення рядового сервера Windows Server до ролі контролера домену Active Directory, створення нового лісу/домену або додавання контролера до вже існуючого домену.

## 4. Висновки

Під час виконання лабораторної роботи №5:
1. Набуто практичних навичок розгортання та адміністрування базових мережевих служб Microsoft Windows Server: контролера домену Active Directory Domain Services (AD DS), служби DNS та служби динамічного розподілу адрес DHCP.
2. Засвоєно принципи побудови ієрархічної структури домену за допомогою оснастки `Active Directory Users and Computers` (`dsa.msc`), створено організаційні підрозділи (OU), користувачів та глобальні групи безпеки для відділів компанії.
3. Досліджено механізм застосування об'єктів групової політики (GPO) через `gpmc.msc`, налаштовано автоматичне блокування екрана із захистом паролем, доменні політики складності паролів та захист від перебору паролів (Account Lockout).
4. Опановано методи створення спільних мережевих папок (SMB/NTFS), підключення домашніх мережевих дисків та конфігурування переміщуваних і обов'язкових (`Ntuser.man`) профілів користувачів.
5. Розглянуто використання підвищення привілеїв через механізм `Run As` та принципи автоматизованої міграції служб звітності SQL Server Reporting Services за допомогою утиліти `rs.exe`.
